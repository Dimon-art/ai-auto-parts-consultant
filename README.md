# AI Auto Parts Consultant

Локальный AI-сервис для демонстрационного подбора автозапчастей по автомобилю, двигателю и запросу детали.

**Версия: MVP Demo v0.1**

Проект предназначен для локальной демонстрации рабочего сценария подбора запчасти с использованием локально сохранённых данных PartsAPI и AI-объяснения результата.

---

## Что работает

- выбор автомобиля: Марка → Модель → Год → Двигатель;
- поиск запчасти по запросу детали;
- поиск по сохранённым fitment-связям;
- использование локально сохранённых данных PartsAPI;
- отображение артикула, бренда, OEM и характеристик;
- AI-объяснение найденного варианта;
- предупреждение о необходимости дополнительной проверки совместимости;
- VIN-интерфейс;
- Compare и Save как элементы интерфейса следующей версии;
- запуск в Docker;
- сохранение SQLite через Docker persistent volume.

## PartsAPI

В текущем MVP PartsAPI используется как источник данных каталога.

Данные, необходимые для демонстрации, были получены заранее и сохранены локально.

В обычном демонстрационном сценарии новые запросы к PartsAPI не выполняются.

Для основного сценария используются:

```text
CAR_ID = 124239
STR_ID = 100470
```

В локальной базе сохранено:

```text
partsapi_articles: 10
partsapi_fitments: 10
```

Связь данных:

```text
CAR_ID
   ↓
STR_ID
   ↓
PartsAPI article
```

Источник сохранённых связей:

```text
PartsAPI getArticles
```

## AI Assistant

AI Assistant получает информацию об автомобиле, двигателе, детали и найденной статье PartsAPI.

Он формирует понятное объяснение результата для пользователя.

Ответ может содержать:

- найденную деталь;
- артикул;
- бренд;
- OEM;
- объяснение результата;
- предупреждение о необходимости дополнительной проверки перед покупкой.

## Запуск

Перейдите в каталог проекта:

```powershell
cd C:\Users\user\ai-auto-parts-consultant
```

Запустите приложение:

```powershell
docker compose up -d
```

Проверьте состояние контейнера:

```powershell
docker compose ps
```

Откройте приложение:

```text
http://localhost:8023
```

`localhost` доступен только на компьютере, где запущен Docker.

## Проверка API

Для проверки backend:

```powershell
$body = @{
    make = "Volkswagen"
    model = "Golf"
    year = 2018
    engine = "1.0L TSI 6MT FWD (110 HP)"
    part_request = "Масляный фильтр"
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8023/query" `
    -Method POST `
    -ContentType "application/json; charset=utf-8" `
    -Body $body
```

Ожидаемый результат:

- HTTP 200;
- найденные варианты;
- данные PartsAPI;
- статья `L40635`;
- AI-ответ.

## Что не входит в MVP

В текущей версии не реализованы:

- полноценный VIN-декодер;
- реальная VIN-проверка;
- точный `getApplicability` для каждой отдельной статьи;
- динамическая проверка каждой статьи через PartsAPI;
- полноценное сравнение запчастей;
- сохранение избранных запчастей;
- заказ запчастей;
- корзина;
- реальные цены и наличие интернет-магазинов;
- авторизация пользователей;
- личный кабинет;
- платежи;
- production deployment;
- массовая загрузка полного каталога PartsAPI.

---

## Ограничения

Это демонстрационный локальный MVP, а не коммерческий онлайн-каталог.

Данные PartsAPI, необходимые для текущей демонстрации, сохранены локально.

Сохранённые fitment-связи используются для демонстрации механизма подбора.

Подтверждение применяемости каждой отдельной статьи через `getApplicability` в текущей версии не реализовано.

Перед реальной покупкой необходимо дополнительно проверять:

- VIN;
- OEM;
- размеры;
- характеристики;
- конкретную модификацию автомобиля.

## Безопасность

Файл `.env` содержит секретные настройки и не должен попадать в Git.

Резервные копии и временные файлы не являются частью основного исходного кода проекта.

Не используйте:

```powershell
docker compose down -v
```

если нужно сохранить данные Docker volume.

Эта команда удаляет volume и находящиеся в нём данные.
